## Objective

Add Umami analytics tracking to the Barbets Duet site via the root layout. Umami is privacy-first (no cookies, no GDPR consent banner needed) and runs on a 100k events/month free tier.

---

## Context

**Parent Feature:** Barbets Duet — Full Platform Build

Barbets Duet needs basic traffic analytics to understand which learning sites attract the most interest, which user journeys complete (discovery → volunteer application → donation), and where drop-off occurs. Umami provides this without requiring cookie consent banners — important for a conservation organisation that values ecological and digital ethics alignment.

This task is **Wave 1** — no dependencies, can run in parallel with T01/T02/T03/T05.

## Implementation Guidance

### Script Tag Pattern

```tsx
// app/layout.tsx
import Script from 'next/script';

// Inside RootLayout, before </body>:
{process.env.NODE_ENV === 'production' && process.env.NEXT_PUBLIC_UMAMI_WEBSITE_ID && (
  <Script
    src="https://cloud.umami.is/script.js"
    data-website-id={process.env.NEXT_PUBLIC_UMAMI_WEBSITE_ID}
    strategy="afterInteractive"
  />
)}
```

### Environment Variable

```bash
# .env.local.example
NEXT_PUBLIC_UMAMI_WEBSITE_ID=your-umami-website-id-here
```

The actual website ID is generated in the Umami Cloud dashboard when you create the Barbets Duet website. Store the real value in `.env.local` (which is gitignored).

### Why Umami Needs No Consent Banner

Umami does not use cookies or local storage for tracking. It uses server-side session hashing. This means:
- No GDPR cookie banner required
- No ePrivacy directive issues
- Fully privacy-compliant out of the box

Do NOT add any cookie consent UI component — it is explicitly not needed and would be misleading.

### Tracking Key Events (note for later)

Umami supports custom events via `umami.track()`. The volunteer form submission and donation checkout initiation should be tracked in T14/T15 respectively. This task just installs the base script.
