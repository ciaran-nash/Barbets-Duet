## Objective

Add an optional `projects?: Project[]` field to the `LearningSite` interface, and add a new GROQ query helper `getProjectsBySite(siteSlug)` to `lib/sanity/queries.ts`. This establishes the reverse relationship from learning sites to their associated projects, allowing learning site detail pages to list their projects without scanning all projects manually.

---

## Context

**Parent Feature:** data-model-unify (PRD-C schema cleanup)

Currently, `Project` has `siteSlug: string` — a forward reference to its learning site. But `LearningSite` has no corresponding `projects[]` field. To list a site's projects, code must scan all projects and filter by `siteSlug` — inefficient and untypable without loading all project data.

The Sanity schema for `project` uses an `associatedSite` reference field. The GROQ projection already maps it back: `"siteSlug": associatedSite->slug.current`. A reverse traversal query can fetch projects by site slug directly.

**Key constraint:** `projects?` is optional on `LearningSite`. The static data in `lib/data/learning-sites.ts` does not include a `projects` array, and must not break. The field should only be populated by the detail-view query (`getLearningSiteFromSanity`), not the list query (`getAllLearningSitesFromSanity`), to keep list payloads small.

After C2 completes, `LearningSite.impactData` will use `ImpactPoint[]` instead of `ImpactStat[]`. Read `types/learning-site.ts` as it exists after C2 before making changes.

This task is part of **Wave 2** — runs in parallel with C3 and C4, after C2 completes.

```typescript
/**
 * Fetch all projects associated with a given learning site slug.
 * Uses reverse reference traversal: project.associatedSite->slug.current == siteSlug.
 * Cache tags: ['project', `project:site:${siteSlug}`]
 */
export async function getProjectsBySite(siteSlug: string): Promise<Project[]> {
  if (!process.env.NEXT_PUBLIC_SANITY_PROJECT_ID) return [];

  return sanityClient.fetch<Project[]>(
    `*[_type == "project" && associatedSite->slug.current == $siteSlug] | order(maturity asc) {
      "slug": slug.current,
      title,
      description,
      category,
      "siteSlug": associatedSite->slug.current,
      maturity,
      "image": image.asset->url,
      featured,
      impactMetrics[] { label, value, unit },
      innovationSummary,
      longDescription
    }`,
    { siteSlug },
    { next: { tags: ['project', `project:site:${siteSlug}`] } }
  );
}
```
